## Phase 7: Real Supabase Auth, Auto Config & PostgreSQL Row Level Security (RLS)
- [x] Requirement 1: Automatic Connection & Anon Key Verification
    - Removed manual "Supabase Cloud Real-time Connection" modal for normal users.
    - Created `config.js` defining `window.DEPOSTER_CONFIG` with `SUPABASE_URL` and `SUPABASE_ANON_KEY`.
    - Cryptographically verified that the key payload is strictly the public anon key (`role: "anon"`), NEVER `service_role`.
    - Every device and client connects automatically with zero manual setup.
- [x] Requirement 2: Real Supabase Auth, Profiles Table & Role Authority
    - Removed simulated Admin/Staff toggle switcher buttons.
    - Built editorial warm paper Login view (#loginView) matching design specifications:
        - Warm paper background `#F4EFE6`, `#1B1A17` ink, `#B4570F` burnt-orange button and tabs.
        - Bricolage Grotesque headings, DM Sans body, 48px touch inputs.
        - Email/username + password inputs, Show/Hide password toggle.
        - Portal mode intent tabs (Admin Dispatcher / Staff Booking) with explicit security notice.
        - One-click demo chips for quick testing.
    - PostgreSQL `public.profiles` table: linked to `auth.users(id)` with `role` (`admin` or `staff`) and `agency`.
    - Server-side role authority: Role is strictly queried and enforced from the user's database `profiles.role`. If a staff member selects Admin in the portal selector, they are safely signed in with their real database role (`staff`), and a notification confirms the database override.
    - Session management: Persistent Supabase auth session, Sign Out button with confirmation, unauthenticated users automatically redirected to `#loginView`.
    - Role badge in header showing verified authority: `ADMIN • Lalitpur Holidays` or `STAFF • Batuwa Trip`.
    - Admin-only Staff Management Modal (`#staffModal`) displaying live database user list and new account registration.
- [x] Requirement 3: Row Level Security (RLS) Policies & Direct API Verification
    - Signed-out users: Zero read/write access (SELECT returns 0 rows).
    - Staff users: Allowed to SELECT departures, packages, and bookings; allowed to INSERT new customer bookings only. Direct API calls to UPDATE or DELETE customers or departures are strictly rejected at the database level.
    - Admin users: Full authorization to SELECT, INSERT, UPDATE, DELETE customer records, edit remaining balances, manage packages, and assign drivers.
    - Verified via automated Node.js test suite (`test_rls_policies.js`): 8 out of 8 tests passed against live Supabase database.
    - Verified via Playwright browser test suite (`test_e2e_auth.js`): Unauthenticated view, Admin login, Staff login, Role override, and Sign out all passed.
- [x] Status: COMPLETE
